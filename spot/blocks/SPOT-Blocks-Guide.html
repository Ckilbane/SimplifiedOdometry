SPOT for Blocks

Before you start

Ten minutes of checking here saves an afternoon of guessing later.

  1. Check the SDK version. On the Driver Station, open the menu, then About. The Robot Controller version must be 10.3 or newer, because that is when the Pinpoint driver was built in. This season's release is 12.0. If it's older, update the Control Hub with the REV Hardware Client first.
  2. Plug in all four drive motor encoder cables. The custom blocks run the drive motors in encoder mode. A motor with no encoder cable can run at full speed when you ask for a little.
  3. Mount the Pinpoint flat, sticker side up, and plug it into a free I2C port on the Control Hub (port 1, 2 or 3). Port 0 already has the hub's built-in IMU.
  4. Plug the pods into the Pinpoint. The pod that rolls when the robot drives forward goes in X. The pod that rolls when the robot strafes goes in Y.
  5. Check each pod by hand. The wheel should press firmly on the floor and spin freely, and the pod shouldn't wiggle on its mount. A pod that lifts off the floor or wobbles gives short or jumpy readings.
  6. Have a laptop that can join the robot's Wi-Fi, plus a tape measure in millimeters.

Install the custom blocks

This is the only step that touches Java, and it's a copy and paste. Do it once per Control Hub.

  1. Connect the laptop to the robot's Wi-Fi network and open http://192.168.43.1:8080 in a browser.
  2. Click the OnBot Java tab.
  3. Click the + (new file) button. Name the file SpotBlocks.java, letter for letter, and make sure it goes in the teamcode folder. Click OK.
  4. Click Copy file below. In the new file, select everything that's already there, then paste over it. Or download SpotBlocks.java and use OnBot Java's Upload Files button in place of steps 3 and 4.
  5. Click the Build Everything button (the wrench). Wait for Build SUCCESSFUL.
  6. Click the Blocks tab and open any OpMode. In the list of block categories on the left, open Java Classes, then SpotBlocks. You should see the orange, blue, purple and green blocks pictured in this guide.

        3
Motor Direction Check

        
Mecanum only works when all four wheels agree on which way is forward. This program spins one wheel at a time so you can see which ones are backwards.

      

      
Build this in Blocks as a new OpMode named Motor Direction Check. It uses only regular blocks, nothing custom. Put the robot on a box so the wheels spin freely.

      

        
Motor Direction Check · regular blocks onlyrepeat for all four motors

        

      

      
    
        
  1. Run it. Each wheel spins for 2 seconds, in order: left front, right front, left back, right back. The Driver Station says which one is spinning.
    2. 
        
  2. For each wheel, ask: would this push the robot forward? The top of the wheel should roll toward the front of the robot.
    3. 
        
  3. Any wheel that spins backwards gets checked as Reversed in the Your robot card. Don't change any wires.
    4. 
      

      
On a goBILDA Strafer, both left wheels usually come out reversed. That's why those two start checked.

    


    
    

      

        4
Measure the pods

        
The Pinpoint needs to know where each pod sits so that turning in place doesn't look like driving.

      

      

        
        

          
Pod type. goBILDA makes two: 4-bar pods have a parallel linkage, and swingarm pods pivot on a single arm. Pick yours in the card.

          
Find the center of the robot: halfway between the left and right wheels, and halfway between the front and back wheels. Mark it with tape.

          
X offset: sideways distance from the center to the X (forward) pod. Left of center is positive, right is negative.

          
Y offset: front-to-back distance from the center to the Y (sideways) pod. Forward of center is positive, behind is negative.

          
Measure to the middle of each pod wheel, in millimeters. Within 5 mm is plenty.

        

      

    


    
    

      

        5
Pinpoint Check

        
Before the robot drives itself, prove that the Pinpoint reads the right numbers in the right direction.

      

      
Make a new OpMode named Pinpoint Check. The orange and green blocks are in Java Classes → SpotBlocks. Tape values come from the card.

      

        
Pinpoint Checkrobot sitting still at INIT

        

      

      
    
        
  1. Set the robot on the floor, press INIT, wait a second, then press Start. Don't touch the robot during INIT, because the Pinpoint is calibrating its gyro.
    2. 
        
  2. Push the robot straight forward by hand along a tape measure, 24 inches. X should read close to +24. If it counts down instead, check X pod reversed in the card, update the block, and run it again.
    3. 
        
  3. Push it 24 inches to the left. Y should read close to +24. If it counts down, check Y pod reversed.
    4. 
        
  4. Turn it left (counter-clockwise from above) a quarter turn. Heading should read close to +90.
    5. 
        
  5. Spin it in place a few times and come back to where it started. X and Y should stay within an inch or two of where they were. If they wander a lot, recheck the pod offsets.
    6.

        6
First autonomous

        
Two short programs. The square shows driving and turning. The box shows what makes mecanum special: sliding sideways without turning.

      

      

        
Every odometry program starts with the same setup stack: the orange blocks with your robot's values, then init robot, then waitForStart, then reset heading. Build the setup stack once, then duplicate the OpMode for each new program.

        
Each blue block finishes its move before the next block starts. You don't need sleep blocks between them.

      

      

        

          
Auto Square24″ square, returns facing start

          

        

        

          
Auto Strafe Boxnever turns

          

        

      

      
Turn to faces a direction. It doesn't turn by an amount. 0 is the way the robot faced at reset heading, 90 is a quarter turn left, -90 is a quarter turn right, and 180 is facing backward. Two turn to 90 blocks in a row only turn once.

      
First run of any new program: use power 0.3 and keep a thumb on Stop. If a pod or motor is reversed, the robot may drive off. SpotBlocks stops it within about 6 inches and shows a message that starts with SPOT stopped the robot. See Troubleshooting.

      
To score, put your team's own mechanism blocks (arm, intake, servo) between the blue blocks. For example: drive 30, then set the claw servo to open, then sleep 500, then drive -10.

    


    
    

      

        7
Tuning

        
The default numbers work on most goBILDA mecanum robots. Tune only after the Pinpoint Check and Motor Direction Check pass, and change one number at a time.

      

      

        

          
Tuning additionsafter init robot

          

        

        

          
Gain is how hard the robot pushes for each inch (or degree) it still has to go. Defaults: drive 0.03, strafe 0.03, turn 0.018.

          
Power in each blue block is the top speed. Start at 0.5. Faster runs are less precise.

          
Hold is how long the robot has to stay on target before the block finishes. 0.25 seconds is a good start. Use 0 when you want speed and don't mind being off by a little.

        

      

      

        

          
What you seeTry this

          
            
Robot stops short, or creeps slowly the last inchRaise that move's gain a little (drive 0.03 → 0.035).

            
Robot overshoots and rocks back and forth at the endLower that move's gain (0.03 → 0.025), or lower the power.

            
A block never finishes and the robot just sits there hummingIt's stuck within a fraction of an inch. Raise the gain a bit, or lower the hold time. Press Stop to get out.

            
Turns end a degree or two offRaise turn gain (0.018 → 0.022). Make sure the battery is charged.

          
        

      

      
Robot driving off, spinning or stopping with a message? That isn't a tuning problem. See Troubleshooting.

    


    
    

      

        8
Troubleshooting

        
Find what your robot did in the tables below. Almost every problem is a sensor or a motor set up backwards, and two checks you already built will find it.

      

      

        
Run the Pinpoint CheckPush the robot by hand and compare the readings to the table in Phase 5. This finds pod and Pinpoint problems.

        
Run the Motor Direction CheckOnly if the Pinpoint Check passes. This finds reversed or swapped motors (Phase 3).

        
Then tuneOnly if both checks pass and the robot is just a little off (Phase 7).

Error messages
the program stops and the Driver Station shows one of these

      

        

          
Message starts withFix

          
            
SPOT stopped the robot: it drove AWAY…
SPOT stopped the robot: it strafed AWAY…		A pod counts backwards or the X and Y pods are swapped, or motors are reversed. Run the Pinpoint Check, then the Motor Direction Check. See the first table.

            
SPOT stopped the robot: it turned AWAY…The Pinpoint is upside down, or the motor directions are wrong. Pinpoint Check: turning left must make heading go up.

            
SPOT stopped the robot: it was told to drive (or strafe, or turn), but the Pinpoint measured no…A pod is unplugged, off the floor, or swapped, or the wheels aren't turning. If the robot spun or drove forward on a strafe, a front and back motor are swapped.

            
SPOT stopped the robot: it turned more than 45 degrees while trying to go straight…One motor is reversed, or the heading counts backwards. Motor Direction Check first.

            
SPOT stopped the robot: it stopped getting closer to its target…The robot is pushing against a wall or a game element, or a wheel is stuck. Clear the path, or shorten the move.

            
Put the "init robot" block in your program…Add init robot after the orange set blocks and before waitForStart.

            
Pod type must be 4-bar or swingarm…Fix the text in set odometry pods.

            
The "drive" block needs a power between 0 and 1…Power is always positive. To go backward, make the inches negative. To turn right, make the heading negative.

            
Unable to find a hardware device with the name…A configuration name doesn't match Phase 1, or the wrong configuration is active.

            
Move the "set …" block ABOVE "init robot"…This copy of SpotBlocks is out of date. Update it (Phase 2). Your blocks are fine.
